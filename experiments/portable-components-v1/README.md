# Focused portable CPU notebooks

Six standalone notebooks embed only bootstrap/check orchestration and a pinned file manifest. Engine source and existing tests come from commit `b4e890b0dbc93169ac278454b92bcd0371e19c8b`, version `0.2.6`. See PLAN.md. Local candidate records are maintained outside the public worktree; no remote run claimed.

| Notebook | Methods | Scope |
|---|---:|---|
| [profiling-prose](profiling-prose.ipynb) | 4 | Task formatting profile, strict prose JSON extraction with invalid-number/duplicate-key controls, complete context and settings refusal. No semantic model or provider. |
| [typed-plans](typed-plans.ipynb) | 14 | Registered pure typed plans and settings, invalid graphs/values and branch boundaries. No durable scheduler or sandbox. |
| [composition-recovery](composition-recovery.ipynb) | 10 | Arithmetic graph oracle, branch isolation, failure records, validators, saved-plan fresh-process recovery and contact/prose/profile fixtures. Local files and subprocesses; not operational queue recovery. |
| [omninode-authority](omninode-authority.ipynb) | 37 | Authored adaptive parts/fallbacks, child and root permissions, own forms/checks, legitimate child forms and retention policy. No model calls or external writer qualification. |
| [ancestor-budgets](ancestor-budgets.ipynb) | 35 | Sequential ancestor accounting, repeated/fresh runs, stale child handles, reported failed-probe costs, zero-cost fallback and mandatory stops. No concurrent reservations or callback interruption. |
| [privacy-and-model-authority](privacy-and-model-authority.ipynb) | 19 | Fail-closed record task-text/summary redaction, monotonic data_use authority, ancestor and runtime part/connector model allowlists, body-only boundary provenance, strict-JSON vs envelope/fence boundary diagnostics, and declarative grid conformance gates. Local CPU fixtures only; no live models or service substrates. |

Methods are not individual assertions or unique tasks. Focused subsets overlap the separate full 113-method package gate; composition adds 10 methods. These do not qualify all modules, models, private providers or a month of operation. Imported package bytes must match the pin; context and per-method results are recorded, skips/refusals during setup are not passing runs.

The anonymous GitHub setup requires internet when a user executes it remotely. This work made no Kaggle/network requests. Local route uses an offline wheel plus installed host numerical dependencies. Every rerun writes a new attempt directory. Failures, logs, imported module paths, source hashes, dependency versions and expected/actual method counts remain inspectable.
