# Teleion Fabric charter

North star: **a universal, self-optimizing, task-aware solutioning fabric**.

Receive an input; establish intent and acceptance; profile its shape, meaning and constraints; retrieve reusable solutions and experience; select a suitable harness/model/context/tools/skills; compose typed engines; execute through durable workers; check the outcome; retain evidence; improve every layer under externally governed constraints.

Everything reusable can expose an OmniNode contract. This includes deterministic functions, models, harnesses, search, compilers, stores, queue workers, memory, training, weight editing and complete workflows. A Python package is a distribution boundary, not necessarily one process, model or node. A remote engine can supply a Python client. Several modules may belong to one versioned distribution. No package needs to expose its implementation to a planner.

Each edge describes types, semantic meaning, units, locale, missingness, versions, preconditions, postconditions, effects, permissions, resources, errors and evidence. Matching JSON shapes alone is insufficient. A reusable composition declares its own edges. Plans select admitted IDs and versions; deterministic code wires them. Unknown engines remain missing dependencies, never fabricated results.

The durable queue owns scheduling, leases, attempts, dependencies and completion. The Task Object store owns versioned content and reusable definitions. Content persistence alone does not complete a queued task. Effect reconciliation precedes retry. Existing provider engines retain ownership behind adapters.

Memory distinguishes current intent, semantic concepts, procedures, episodes, evidence, failures and superseded decisions. Vectors and heat maps describe proximity, not truth or authority. Every participating harness receives the complete compact architecture register and retrieves detailed cards as needed. Context limits are explicit. Instructions cannot force unrelated applications to load them.

Optimization covers profiling, granularity, decomposition, composition, retrieval, reuse, harness/version, model/weights, context, skills, tools, scheduling, checking, budgets and improvement policies. Exact matches, similar prior solutions, method reuse and effect replay are separate decisions. Training, generated examples, embedding transforms, adapters, masks and direct weight editing are candidate mechanisms with lineage and held-out regressions; none is assumed best.

Every experiment begins with a plan, fixed scoring rules and appropriate controls. Distinguish component tests, replays, integrated workflows and real operations. Failures stay recorded. A separate checker reviews important results. At least a month on real tasks is required before broad operational optimization guidance; repairs and bounded component tests remain useful now. Time alone never promotes a policy.

Public packaging proceeds by explicit source allowlists. Private histories, credentials, customer records, downloaded model weights and provider-owned internals are excluded. Every known engine has a migration status. A catalog entry is not an installed implementation. Publication or installation does not establish full integration or AGI.
